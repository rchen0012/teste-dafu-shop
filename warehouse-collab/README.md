# 订单箱数核验 · 仓库内网多人协作版

新增 Google Sheets 后端适配器，见 `google-sheets/README.md`。目前该后端尚未授权或启用；没有 `data/google-sheets.json` 的已启用配置时，服务继续使用原 SQLite。启用 Google Sheets 后，仓库电脑需要联网。

基于你提供的原页面和 https://rchen0012.github.io/teste-dafu-shop/ 的页面源码改造。保留扫码枪、手机扫码、手动添加、定位、数量键盘、差异汇总和 CSV 导出。所有设备加入同一任务后，扫描一次完整的 8 位订单号，共享实际箱数加一。

## 先知道这三点

1. 这是**可以在仓库电脑运行的完整程序**，不能只双击 HTML，也不能只上传到 GitHub Pages。GitHub Pages 不能运行这个 Node.js 服务。原 GitHub 网站没有被修改。
2. 仓库电脑需开机、禁止自动睡眠，所有设备连接允许设备互访的同一 Wi-Fi。给电脑在路由器上设置固定 DHCP 地址。不要用访客 Wi-Fi，也不要开启 AP 隔离。
3. 手机摄像头需要受信任的 HTTPS。本程序带 HTTPS 配置脚本。扫码库已随包保存，不需要手机访问外网；电脑只在首次安装 Node.js 时需要联网。

## 一、启动仓库电脑

1. 从 https://nodejs.org/ 安装 **Node.js 24 LTS 或更新版本**。无需 npm install，没有第三方服务端依赖。
2. 将整个文件夹解压到仓库电脑固定位置，例如 `D:\WarehouseCounter`。不要放到公共共享盘，不要把 data/certs 上传 GitHub。
3. 双击 `start.cmd`。保持窗口打开。默认 HTTP 端口为 8080，HTTPS 为 8443。
4. 在仓库电脑访问 `http://localhost:8080`，填写姓名和任务名称，点击“创建任务”。
5. 将任务码发给同仓库同事。同事打开启动窗口列出的内网地址，填写姓名和任务码，点击“加入任务”。任务码相当于加入凭证，仅分享给获准协作的人。

扫码枪设置为“键盘模式 + 扫码后回车”，点击页面订单号输入框后使用。每扫描一次增加一箱，扫码枪及手动添加无需配置摄像头。

## 二、配置手机摄像头 HTTPS

在仓库电脑 PowerShell 中执行（将 IP 改成仓库电脑实际 IPv4 地址；可运行 `ipconfig` 查询）：

```powershell
cd D:\WarehouseCounter
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-https.ps1 -WarehouseIP 192.168.1.100
```

脚本为此仓库生成专用根证书及有效期一年的服务器证书，并让当前 Windows 用户信任根证书。脚本不需要管理员，但受公司设备策略限制时需要 IT 协助。脚本使用 Windows 自带 PKI 证书命令；不要在非 Windows 系统执行。

关闭旧的启动窗口，重新双击 `start.cmd`。手机先打开：

```text
http://192.168.1.100:8080/warehouse-root.cer
```

只安装从自己仓库电脑下载的证书。该根证书的 SHA-256 指纹可以在仓库电脑运行以下命令核对：

```powershell
certutil -hashfile .\certs\warehouse-root.cer SHA256
```

- **iPhone/iPad**：在 Safari 下载后，到“设置 → 通用 → VPN 与设备管理”安装描述文件，再到“设置 → 通用 → 关于本机 → 证书信任设置”开启对 Warehouse Local Root 的完全信任。名称和路径可能因系统版本不同而变化。
- **Android**：下载后到系统设置中的“安全/加密与凭据 → 安装证书 → CA 证书”安装；具体入口因品牌和版本不同而变化。若手机受公司管理不允许安装，交给 IT 处理。
- **其他电脑**：安装根证书到当前用户“受信任的根证书颁发机构”。

之后所有设备统一打开：

```text
https://192.168.1.100:8443
```

确认浏览器没有证书警告，再允许摄像头权限。**仅点击跳过证书警告不能替代信任证书。** 请在 Safari/Chrome 等浏览器里打开，不要依赖聊天应用内置浏览器。

HTTP 和 HTTPS 是不同来源，会话不共用。正式工作前先配置 HTTPS，并让所有设备在 HTTPS 创建/加入任务，避免在两个来源间切换丢失管理员会话。

### Windows 防火墙

如手机打不开页面，将仓库 Wi-Fi 标记为可信任的“专用网络”。需要时由管理员 PowerShell 执行，仅允许本地子网：

```powershell
New-NetFirewallRule -DisplayName 'Warehouse Counter LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080,8443 -Profile Private -RemoteAddress LocalSubnet
```

不要在路由器上配置端口转发，不需要将服务开放到互联网。

## 三、每天使用

1. 创建人作为管理员创建当次核验任务，成员用任务码加入。姓名用于记录操作，是自行填写的标识，不是实名身份验证。
2. 扫码枪/手机每次有效提交一次 `+1`。服务端事务累计，多人同时扫同一订单不会互相覆盖。
3. 预估最初显示“待填写”。任一成员点击该订单的“预估”填写共享预估总数；填写预估不会额外加箱，不影响其他成员扫码。
4. 手机支持二维码及 CODE_128、CODE_39、ITF、EAN_8 条码。识别结果必须完整匹配 8 位数字，长码不截取、夹杂文字不提取。原先仅支持二维码。
5. **同一码停在镜头中只记一次。下一箱也是相同订单时，移开上一箱，点击“同一订单：扫描下一箱”，再对准新箱。** 这是防止静止条码被视频逐帧重复计数；不同订单切换可直接识别。
6. “+ / −”和修改实际总数需要填写原因。修改实际/预估有独立版本检查，避免覆盖他人修改；有人扫码时，过期的“修改实际总数”会被拒绝，重新打开弹窗后确认。
7. 数量只在服务端确认后显示保存成功。网络断开暂停新提交；如果响应结果不明，页面显示待确认操作。恢复后点击“核对并重试”，使用原操作 ID，即使服务端已保存也不会重复加箱。刷新页面仍保留该待确认记录。**不要重新扫描同一箱来代替重试。** 不支持离线批量扫码。
8. 任务创建人可“结束并归档任务”。所有成员立即停止提交，数据保留，可查看/导出。普通成员无权归档。没有共享清空按钮。
9. 可查看最近 100 条操作，也可导出本任务完整操作记录 JSON；原 CSV 导出保留。未填写预估的订单仍需人工补全，汇总差异以当前已录入数值计算，预估待填按 0 计算。

管理员权限绑定当前浏览器保存的随机会话。关闭再打开同一浏览器/同一网址可恢复；请勿清理站点数据或使用无痕浏览器。**任务码只能恢复普通成员身份，不能恢复管理员身份。** 归档前不建议管理员退出任务。任务码不提供面向公网的账号安全保障，此版本按可信仓库内网设计。

## 四、备份、证书更新和迁移

- 数据保存在 `data/warehouse.sqlite`，会自动持久化。需完整备份时先停止服务，再复制整个 `data` 文件夹；不要运行中只复制 sqlite 文件，运行中可能有 WAL 文件。
- `certs/server.pfx`、`certs/https.json` 包含服务器私钥及其口令。该目录由配置脚本限制为当前 Windows 用户与 SYSTEM 可读。不得发给手机、提交 GitHub 或通过网页共享。网页仅提供公开根证书。
- 换电脑时停服后迁移完整目录，重新检查 Windows 文件权限、IP 与防火墙；手机需要信任新生成的根证书。
- 电脑 IP 变更或证书一年到期：停服，妥善保管原 certs 目录，将其重命名为 `certs-old`，再次运行配置脚本，再让手机信任新根证书。旧根证书可以从设备信任列表移除。建议固定电脑 IP，避免频繁变更。
- 本服务默认监听所有网卡，防火墙请限定专用网络的本地子网。
