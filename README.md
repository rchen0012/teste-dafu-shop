# 订单箱数核验 · Google Sheets 多人协作

直接打开 [扫码网站](https://rchen0012.github.io/teste-dafu-shop/)。网页连接 Google Apps Script，数据保存到 Google Sheets，**无需本地服务器、仓库电脑常开或安装自签名证书**。设备需要能访问 Google 服务。

## 使用

1. 填写姓名和任务名称，点击“创建任务”。创建人拥有该任务的管理员权限。
2. 其他成员填写姓名和8位数字任务码加入（原16位任务码仍可使用）。任务码仅发给获准协作的人。
3. 手机摄像头、扫码枪、手动输入共用同一个任务。每次扫描完整的8位订单号，实际箱数加一。
4. 第二箱强制填写预估箱数；预估修改冲突时明确选择采用云端值或本机值，扫码增量继续保留。
5. 扫码仅保存到当前设备；到页面顶部下拉或点击“上传并合并云端数据”才上传本机记录并下载其他成员数量。不定时同步。重试沿用原操作编号，避免重复计数。
6. 所有成员先分别手动上传，管理员再结束并归档任务。历史数据保留，可导出 CSV 和扫码明细。

手机使用浏览器打开正式网站，并允许摄像头。摄像头支持连续扫码：上一箱移出镜头约1秒再放下一箱，会自动恢复识别；不同订单可连续识别。同一箱请勿反复移入镜头。需要时可点“重新识别”手动准备下一箱。扫码枪设置为键盘模式，并在扫码后发送回车。

管理员身份保存在当前浏览器会话中。请勿清理站点存储或使用无痕模式；任务码不能恢复管理员身份。

## 数据与权限

- Google 表格保持“受限”，扫码成员不需要表格编辑权限。
- 浏览器只保存自己的成员会话令牌，公开代码不包含服务端密钥。
- 同一任务的读写需要成员会话，归档需要管理员身份。
- 脚本锁串行处理计数，订单数量、任务版本与操作记录通过同一原子批次保存。重复操作 ID 不会重复加箱。
- 公开页面只能调用任务业务接口，无法调用签名保护的历史导入接口。
- 不要直接修改、排序或删除数据页中的行。业务修改在网页操作，否则可能破坏版本和去重记录。
- Google API 配额或连接故障会暂停提交，不支持离线扫码。

## 源码

- `index.html`：正式扫码界面。
- `assets/cloud-client.js`：浏览器与 Google 托管接口的通信。
- `assets/collaboration.js`：任务、成员、扫码及同步逻辑。
- `warehouse-collab/google-sheets/Code.gs`：Google Apps Script 后端。
- `warehouse-collab/test/`：权限、累计、去重及迁移测试。

`warehouse-collab` 中的 Node.js、SQLite、内网证书脚本保留为历史方案和备份，正式网站不再依赖它们，也不需要运行 `start.cmd`。

后端授权和部署步骤见 [Google Sheets 直连配置](DIRECT_SHEETS.md)。

下拉或点击更新时显示 DAFU Logo 动画，依次上传本机待同步操作、读取当前任务云端数量与扫码明细。手势中途取消或横向滑动不会触发同步。

管理员可在页面使用“清除全部云端数据”：校验密码、输入确认文字，自动备份四张业务表后统一清除。首次密码由表格所有者在 Google 后台亲自设置，步骤见 [管理员密码与恢复说明](ADMIN_RESET.md)。任务记录缺失但原管理员会话还在时，页面提供从本机最后云端快照恢复并继续同步的入口。

填写预估数量后，少扫也会列入异常，显示缺少箱数；补齐后自动解除数量异常。异常页和当前订单可展开逐箱时间、操作人与撤销记录。人工标记独立保留。手机摄像头采用响应式大识别框、20fps、兼容的后置摄像头高清请求与可用时连续对焦；同一订单的下一箱移出约半秒后可继续识别。

页面支持手机、平板和宽屏布局，扫码模块固定排在内容最上方。可使用“重新核对云端任务状态”或“清除本机旧缓存”修复旧快照；身份、管理权限与待上传记录保留。结束任务前会核对状态并先确认待上传操作，重复结束不会重复归档。云端全库清除的再次确认数字为123456，管理员密码仍独立校验。
